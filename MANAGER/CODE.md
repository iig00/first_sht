# コードの編集規則

- 本文書で定める作業による変更は、AGENTS.mdの「承認依頼と許可」の適用対象外とする。

## 対象

- アプリのコードと、動作・ビルドに必要な設定を対象とする。
- Manifest、設定XML、依存関係・ビルド設定など、アプリのビルドや動作を変える編集も実装に含む。
  外部依存物の管理操作はDEPENDENCIES.mdで扱う。
- PLANの編集は仕様の編集であり、実装に含めない。

- 簡易テスト、全体テスト、
  外部依存物の管理は、それぞれ別の作業範囲とする。

## 作業の単位

- 一度に作業する範囲は、PLAN/IMPLEMENTATION.mdの一項目とする。

- 承認対象に、変更するファイルと実装する内容を明記する。

## 作業前の確認

- 対象項目に必要なSPEC・アーキテクチャの検討が完了し、
  未決定事項が残っていないこと。
- 対象範囲のPLANの確認・修正が完了するまで、実装へ移らない。

- 既存コードと接続先を確認し、変更の影響範囲を把握する。

## Codexが判断して実装すること

- 決定済みのSPECとDESIGNを守る範囲で、
  内部処理、関数構成、変数、処理手順などを判断する。

- クラスや関数には、役割が分かる説明コメントを必要に応じて記述する。

- 対象項目の実現に必要のない機能追加・共通化・構造変更は行わない。

## 仕様や作業範囲の変更が必要な場合

- 仕様の不足・矛盾をコード側で独自に解消しない。

- 仕様変更、外部依存物の変更、
  対象外ファイルの編集が必要になった場合は、
  必要な内容と影響を報告し、別途承認を得る。

- 問題の発生により作業を停止した後の再開は、
  AGENTS.mdの承認規則に従う。

## 編集後の確認

- 対象項目の実装内容が揃っていること。

- SPEC・DESIGN・architecture.mdに反していないこと。

- 呼び出し元・接続先との整合が取れていること。

- 承認範囲外の変更がないこと。

- 簡易テストと全体テストは、コード作成とは別の作業範囲として扱う。
  コードの確認だけで、テスト済みとは報告しない。

## 作業終了時の報告

- 実装した内容、確認した内容、残る未確認事項を区別して報告する。
- 対象範囲に残る未決定事項の扱いを明示する。

- IMPLEMENTATION.mdの状態は、AGENTS.mdの更新規則に従う。
