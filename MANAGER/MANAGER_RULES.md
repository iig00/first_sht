# MANAGERの運用

## 目的と適用

- MANAGERは、作業対象ごとの進め方、確認基準を定める。

- 共通の承認・編集範囲・状態更新・作業記録の規則は、AGENTS.mdに従う。

- MANAGERの記載は、作業の開始や承認範囲の拡張を許可するものではない。

- MANAGERの追加・変更・削除は、AGENTS.mdの変更制限に従う。

## 参照先

- 作業対象ごとの参照先を以下に示す。

### PLAN

| 作業対象 | 参照先 |
|---|---|
| PLAN/SPEC/ | SPEC.md |
| PLAN/DESIGN/ | DESIGN.md |
| PLAN/architecture.md | ARCHITECTURE.md |
| PLAN/SCHEDULE.md | SCHEDULE.md |
| PLAN/IMPLEMENTATION.md | IMPLEMENTATION.md |

### 実装

| 作業対象 | 参照先 |
|---|---|
| コードと動作・ビルドに必要な設定 | CODE.md |
| 簡易テスト | SIMPLE_TEST.md |
| 全体テスト | FULL_TEST.md |

### それ以外

| 作業対象 | 参照先 |
|---|---|
| 外部依存物の管理 | DEPENDENCIES.md |

### 共通の参照方法

- 参照先は、このMANAGER_RULES.mdと同じフォルダ内の文書とする。

- 作業対象を切り替える場合は、切り替え先の規則を確認する。

- 複数の対象に関係する場合も、作業範囲を分け、
  AGENTS.mdの承認規則に従う。
## 編集規則
### PLANの編集規則

- PLANの編集は、仕様・設計・作業計画とその状態を文書に反映する作業とする。
- 各項目の編集は、「参照先」のPLANに示した規則に従う。
- PLANの編集を、コードや動作・ビルド設定の変更への許可として扱わない。
- PLANの項目は、SPEC → DESIGN → architecture.md → SCHEDULE.md
  → IMPLEMENTATION.mdの順に作成する。
- 整合性チェック
  - PLANの不整合を確認し、整合のとれる形に修正を行う
  - 対象範囲の個別修正が一段落した後、別工程として整合性を確認する
  - 整合性チェックは、SPECから照合し順に作成・変更を行い  
    IMPLEMENTATION.mdまで作成・変更を行う。
  - 整合性チェック完了時にはPLAN\IMPLEMENTATION.mdの[_]整合性チェックを[✓]に変更すること




### 実装の編集規則

- 実装は、決定済みのPLANに基づくコード・設定・テストの作業とする。
- 各項目の編集・実行は、「参照先」の実装に示した規則に従う。
- 実装中にPLANの変更が必要になった場合は、該当するPLANの編集規則に従う。
- 外部依存物の管理は実装とは別に、DEPENDENCIES.mdに従う。
- 実装はIMPLEMENTATION.mdにより編集を管理される。

## プロジェクト文書の配置

- PLAN/には、アプリの仕様・アーキテクチャ・実装状況を分けて配置する。
  - SPEC/：アプリの概要・開発範囲・機能別仕様。詳細な配置はSPEC.mdに従う。
  - architecture.md：全体構成・依存関係の図。運用はARCHITECTURE.mdに従う。
  - DESIGN/：実装方法・領域別設計。詳細な配置と運用はDESIGN.mdに従う。
  - IMPLEMENTATION.md：作業状態・開発順。運用はMANAGER/IMPLEMENTATION.mdに従う。
  - SCHEDULE.md：作業内容・予定。運用はMANAGER/SCHEDULE.mdに従う。

## 指摘への対応

- 確認で見つかった問題や改善案は、次の区分に整理する。
  - 必須修正：決定済み仕様や承認内容に反するもの。
  - 確認が必要：根拠の不足や矛盾により判断できないもの。
  - 任意の改善：現在の完了条件を満たすためには必要ないもの。

- 指摘の根拠と妥当性を確認する。
  指摘されたという理由だけで変更を行わない。

- 任意の改善を、現在の作業の完了条件へ追加しない。

- 対応が承認範囲内か確認し、範囲外の変更や
  問題による停止後の再開は、AGENTS.mdの承認規則に従う。

- 再確認では、修正箇所とその影響を中心に確認する。
  新たな根拠なく検討範囲を広げたり、
  任意の改善を繰り返し追加したりしない。

## 不足・矛盾と結果の報告

- 必要な規則が参照できない場合や、
  規則の不足・曖昧さ・矛盾により判断できない場合は、
  該当箇所と影響を報告する。

- 成果物の作成、確認、テスト実行を区別し、
  実施していない確認を完了したものとして扱わない。

- 最終報告では、実施内容、確認結果、
  未解決事項と未確認事項を取りまとめる。
