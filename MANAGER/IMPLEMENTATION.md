# IMPLEMENTATION.mdの運用

- 本文書で定める作業による変更は、AGENTS.mdの「承認依頼と許可」の適用対象外とする。

## 目的と役割

- PLAN/IMPLEMENTATION.mdは、人間が進捗を把握し、次に行う作業と到達点を指示するための実装リストとする。
- 作業の範囲・順序・依存関係・完了状況を明示し、作業の繰り返し、際限のない変更、無理な着手、項目の無断追加を防ぐ。
- SPECの概要、DESIGNの概要、architecture.md、SCHEDULE.mdの順に整理した内容から作成する。
- 詳細な実装方法はPLAN/DESIGN、作業手順・予定はPLAN/SCHEDULE.mdに記述し、リストでは対象と工程を簡潔に示す。

## リストの構成

- 「完了」「実装中」「将来対応」に分ける。
  - 完了：ID内の全作業と必要な簡易テストを終え、完了条件を満たしたID。
  - 実装中：今回の開発対象として着手を決定したID。  
    前提条件がそろうまで着手を待つIDも含む。  
  - 将来対応：今回の開発対象として着手を決定していないID。
- IDを『実装中』に配置する条件は、以下の条件全てを満たすこととする。
  - 対象ID自身に必要なPLAN詳細がすべて[完了]
  - すべてのPLAN前提IDが「完了」
  - すべてのIMPLEMENT前提IDが「完了」または「実装中」
  - 対象IDが属するINDEX以外に、「実装中」のINDEXがないこと。
- IDには一意の識別子、TITLE、PLAN前提ID、IMPLEMENT前提ID,実施順の子項目を記述する。
- 子項目の状態は、[未着手]・[実施中]・[完了]とする。
- INDEXは複数IDをまとめる開発の区切りとする。
  - `-- 名称 --`を、まとめるID群の後ろに配置する。
  - 直前のINDEXの次から、そのINDEXの直前までのIDをまとめる。最初はリスト先頭からとする。
  - 全体テストをINDEXに対応する作業として記載する。
  - 完了欄へIDを移しても、所属するINDEXが分かるようにする。
  - INDEXは必ず一個は作成すること
- INDEXの配置先は、対象IDと全体テストの状態で決める。
  - 対象IDに「将来対応」が残っている間は、INDEXを「将来対応」に置く。
  - 対象IDがすべて「実装中」または「完了」で、全体テストが完了していない間は、INDEXを「実装中」に置く。
  - 対象IDがすべて「完了」し、全体テストも完了した場合に限り、INDEXを「完了」に置く。
  - INDEXを移動しても、対象IDの所属範囲は変えない。
- 完了の前にPLAN整合性チェックを作成する
  - チェックの状態は[_]:未チェック,[✓]チェック済みとなる
  - PLAN\IMPLEMENTATION.md作成時の状態では[_]とする
  - PLAN\各項目の変更を行うとき[_]に変更
  - PLAN\の不整合が発見されたとき[_]に変更
  - PLAN\の整合性チェックを行ったとき[✓]に変更
  - [_]の時コード実装を行うことはできない
  - 将来対応>実装中>完了への状態移動を行うとき[_]への変更を行わない
  - 実装工程(コード用ファイル作成、コード作成、テスト)のため  
    [未着手]・[実施中]・[完了]の変更が行われるとき[_]への変更を行わない
  - 整合性チェックの実行については、MANAGER\MANAGER_RULES.mdに従うこと。


### 記述例

```text
[✓]PLAN整合性チェック

完了

実装中

将来対応
- ID: I-03 TITLE: xxxxの実装
  - PLAN < I-01, (A-10,B-1)  
    - [未着手] SPEC詳細
    - [未着手] DESIGN詳細
  - IMPLEMENT < I-01, (A-10,B-1)  
    - [未着手] コード作成
    - [未着手] 簡易テスト

-- INDEX名 --
  - [未着手] 全体テスト
```

- 例のI-03は未完了の前提が残るため、将来対応に置く。

### 記述内容
- ID
 - alphabet - 数字　で指示される
 - ID以下はTITLEの実装をPLAN詳細から実装までまとめたもの  
   IMPLEMENTATION.mdではこのブロックで管理される
- TITLE
 - 文字列で指示
 - ID以下の作業内容を端的にまとめたもの
 - 詳しい内容はPLAN\SCHEDULE.mdに記載のこと
- PLAN
 - SPEC詳細,DESIGN詳細をまとめ、前提管理を行うもの
 - `<`の右側に、そのIDの開始に必要な前提IDを列挙する。 
    前提IDのSPEC詳細,DESIGN詳細が共に[完了]の時、前提ID完了とし()から外す
    前提IDのSPEC詳細,DESIGN詳細が片方でも[完了]でなければ、前提ID未完了とし()内に配置する
- SPEC詳細
 - IDに関するSPEC詳細の検討を管理する
 - [未着手] SPEC詳細 // SPEC詳細部分が変更されることはない  
   [未着手]の部分は状態により変更を行う
- DESIGN詳細
 - IDに関するDESIGN詳細の検討を管理する
 - [未着手] DESIGN詳細 // DESIGN詳細部分が変更されることはない  
   [未着手]の部分は状態により変更を行う
- IMPLEMENT
 - コード作成,簡易テストをまとめ、前提管理を行うもの
 - `<`の右側に、そのIDの開始に必要な前提IDを列挙する。 
    前提IDのコード作成,簡易テストが共に[完了]の時、前提ID完了とし()から外す
    前提IDのコード作成,簡易テストが片方でも[完了]でなければ、前提ID未完了とし()内に配置する
- コード作成
 - IDに関するコードの作成を管理する
 - [未着手] コード作成 // コード作成部分が変更されることはない  
   [未着手]の部分は状態により変更を行う
- 簡易テスト
 - IDに関する簡易テストの作成、実行を管理する
 - [未着手] 簡易テスト // 簡易テスト部分が変更されることはない  
   [未着手]の部分は状態により変更を行う
- INDEX
 - INDEXは複数IDをまとめる開発の区切り
 - -- INDEX名 --　　// INDEX名に行う作業を端的にまとめること
- 全体テスト
 - 全体テストの管理
 - INDEX直下に配置される
 - [未着手] 全体テスト // 全体テスト 部分が変更されることはない  
   [未着手]の部分は状態により変更を行う


## 実装リストに従う作業

- 共通
  - 指示された対象と到達点まで進める。リストへの登録や前提の完了だけを、作業開始の指示とは扱わない。
  - 各工程の具体的な作業は、それぞれのMANAGER文書に従う。
- INDEX作業
  - 前提条件：最初に実施するIDの前提が完了している。

  - 作業中：リストに従ってID単位の作業を進める。全対象IDの完了後に全体テストを行う
  - 終了条件：対象ID全て完了に設置かつ全体テスト[完了]。
  - 終了時: INDEX項目を完了に移動
  - 次の作業：到達点と残作業を報告する。次のINDEXを独自に開始しない。
  - 一回のまとまり：INDEXの開始から終了まで。今回進める範囲は利用者の指示に従う。
- ID作業
  - ID作業はPLANとIMPLEMENTに分かれる
  - 前提条件: － (本段階に前提条件はない。下位対象項目の条件に従うこと)
  - 終了条件: 全ての項目が[完了]となること
  - 終了時: ID項目を完了に移動
  - 作業制限：PLANとIMPLEMENTを同時に許可することはない
             別のIDであっても前提条件が揃うなら、一度の作業による変更を許可する
- PLAN作業
  - 前提条件: PLANの前提IDが全て完了となること 
  - 作業中: SPEC詳細,DESIGN詳細の検討を順に行う
  - 終了条件: SPEC詳細,DESIGN詳細が共に[完了]となる
  - 終了時: 各IDのPLANの前提表記を更新する
- IMPLEMENT作業
  - 前提条件: IMPLEMENTの前提IDが全て完了となること 
             IDが実装中に配置されている
  - 作業中: コード作成,簡易テストの作業を順に行う
  - 終了条件: コード作成,簡易テストが共に[完了]となる
  - 終了時: 各IDのIMPLEMENTの前提表記を更新する
            ID作業終了となる
- SPEC詳細作業
  - 前提条件: PLAN作業の前提条件を満たすこと
  - 作業中: SPEC詳細検討を行う
  - 終了条件: SPEC詳細に不備がなくなる
  - 終了時: SPEC詳細を[完了]とする
          　DESIGN詳細検討を行う
- DESIGN詳細作業
  - 前提条件: PLAN作業の前提条件を満たすこと
            　SPEC詳細[完了]であること
  - 作業中: DESIGN詳細検討を行う
  - 終了条件: DESIGN詳細に不備がなくなる
  - 終了時: DESIGN詳細を[完了]とする
           PLAN作業終了となる
- コード作成作業
  - 前提条件: IMPLEMENT作業の前提条件を満たすこと
  - 作業中: コード作成を行う
  - 終了条件: コード作成が完了する
  - 終了時: コード作成を[完了]とする
          　簡易テストを行う
- 簡易テスト作業
  - 前提条件: IMPLEMENT作業の前提条件を満たすこと
            　コード作成[完了]であること
  - 作業中: 簡易テスト作成、実行を行う
  - 終了条件: 簡易テストが成功する
  - 終了時: 簡易テストを[完了]とする
           IMPLEMENT作業の終了となる


## 移動規制
「完了」「実装中」「将来対応」の移動規制を行う
- 完了: 
  - IDは、ID内のPLAN,IMPLEMENTが共に完了しなければ完了に設置できない
  - INDEXは、INDEXの構成内のID全てが完了に配置されている  
    かつ 全体テストが[完了]でなければ完了に設置できない
- 実装中:
  - PLANの項目全て[完了]となる かつ 所属INDEXが実装中にはないID
  - 所属IDが全て実装中、完了にあるINDEX
- 将来対応: 完了、実装中でないもの


## 中断とフィードバック

- 中断時は、現状・理由・残作業・フィードバック先・再開条件を報告する。
- ID内の問題は、関連するSPEC詳細・DESIGN詳細へ返し、再検討が必要な詳細の子項目を[未着手]に戻す。
- ID内の先頭の検討で解決できない問題は、SPEC概要へ返す。
- SPEC詳細・DESIGN詳細から概要の変更が必要になった場合や、全体テスト・INDEX全体に問題がある場合もSPEC概要へ返す。
- フィードバックを理由に作業範囲を独自に拡大しない。後続の完了済み作業への影響は確認して報告する。
- 完了済みコードやテストをどこまで戻すか、INDEXの状態の記述形式、再実行の具体的な手順は未決定事項として扱い、独自に規則を補わない。

## SCHEDULE.mdとの整合

- リスト変更時は、対応するSCHEDULE.mdの箇所を確認する。更新方法はMANAGER/SCHEDULE.mdに従う。
- ID・名称・範囲・順序・INDEXを変更した場合は、対応する予定とのずれを確認する。
- 状態更新だけの場合も、予定への影響があれば反映する。
- 未整合を残す場合は、対象箇所と理由を報告する。
