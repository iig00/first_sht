# ステージ進行フロー

## 対象

- IMPLEMENTATIONのI-04「ステージ進行」に関する設計サブフロー。
- `operations/stage/`が管理するステージ開始、出現予定、クリア、再開始、一時停止の遷移を扱う。
- ステージ内の敵固有の動きと攻撃は`operations/enemy/`と`config/behaviors/`に委ねる。

## 構成要素の責務

| 要素 | 責務 |
|---|---|
| `app/` | 更新ごとの入力とフォーカス変化を受け、一時停止・再開に必要な情報を`operations/stage/`へ渡す。 |
| `config/stages/` | ステージ内の敵の出現順・位置・時刻を提供する。 |
| `operations/stage/` | ステージ状態、経過時間、出現予定、クリア・再開始タイマー、一時停止状態を管理する。 |
| `operations/enemy/` | 出現指示を受けて敵を生成し、個体の行動を更新する。 |
| `systems/` | 更新されたオブジェクトから命中・接触の結果を判定する。 |
| `operations/` | 判定結果を反映し、HPゼロを`operations/stage/`へ通知する。 |
| `rendering/` | 現在のゲーム状態に応じて通常画面、暗転、「STAGE CLEAR」「ALL CLEAR」「PAUSED」を表示する。 |

## 進行

1. ステージ開始時に`operations/stage/`がステージ経過時間と出現予定を初期化し、初期状態を作る。
2. 一時停止中でなければステージ経過時間を進め、予定時刻に達した敵を`operations/enemy/`へ生成依頼する。
   出現予定は他の敵の撃破状況にかかわらず時刻に従って処理する。
3. 自機・敵・弾の更新後、`systems/`の判定と`operations/`による結果反映を行う。
4. 結果反映後にステージ進行条件を評価する。HPがゼロなら再開始へ移る。
5. HPがゼロでなく、出現予定が残っておらず、生存している敵もいない場合にクリアへ移る。
6. どちらの条件にも該当しない場合は、通常のステージ進行を続ける。

## クリアと再開始

- クリア時は「STAGE CLEAR」状態に移り、2秒の進行時間が経過してからSPECの順序に従って次へ進む。
- 最終ステージのクリア後は「ALL CLEAR」状態を保ち、Enter入力でステージ1の初期状態を開始する。
- HPゼロ時は「再開始待ち」状態に移り、ゲーム内状態と通常の更新を停止する。
- 再開始待ちの最初の0.25秒で暗転し、その後の0.75秒は暗転を保つ。合計1秒後に同じステージを初期化し、出現予定を開始時点へ戻す。
- 初期化対象と再開始時の方向入力は[stage.md](../../SPEC/FEATURES/stage.md)に従う。
- 同じ更新でHPゼロと最後の敵撃破が成立した場合、再開始条件を先に処理する。ステージクリア状態へは移らない。

## 一時停止

- Pキー入力またはフォーカス喪失を`operations/stage/`が受け、一時停止状態を管理する。
- 一時停止中は、ステージ経過時間、出現予定、ゲーム内状態と遷移タイマーを進めず、「PAUSED」を重ねて表示する。
- 再開後は一時停止直前の状態とタイマーの残り時間から続ける。フォーカス復帰だけでは再開しない。
- 「ALL CLEAR」状態では一時停止を適用しない。

## 追加時の境界

- ステージ内の敵や出現時刻は`config/stages/`から与え、共通の進行処理に敵固有の条件を持たせない。
- ステージ設定の具体的なファイル形式は、別途決定されるまで定めない。
